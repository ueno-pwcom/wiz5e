# 3Dダンジョン探索RPG（SRD 5.1準拠） 機能仕様書

## 1. プロジェクト概要

### 1.1 目的・コンセプト
本ドキュメントは、古典的なグリッドベース探索RPGと SRD 5.1 風ルールを簡潔に実装したゲームの機能仕様を記述する。
実装は React + Vite で構築され、ゲーム状態管理は Zustand、データ定義は `src/data/`、型定義は `src/types/game.ts` で行う。

### 1.2 主要特徴
* **パーティ編成**: 最大5人のパーティ（前衛3名 / 後衛2名）
* **戦闘ルール**: d20攻撃判定、AC、クリティカル/ファンブル、ダイスベースのダメージ計算
* **休憩/回復**: 宿屋、キャンプ（小休憩・大休憩）、寺院での治療・蘇生
* **データ管理**: 呪文、モンスター、マップ、アイテム、探索イベントを TypeScript データとして管理

## 2. システム構成

### 2.1 技術スタック
* フロントエンド: React + Vite
* 状態管理: Zustand (`src/store/useGameStore.tsx`)
* 型定義: TypeScript (`src/types/game.ts`)
* データ: `src/data/spells.ts`, `src/data/monsters.ts`, `src/data/map1.ts`, `src/data/items.ts`, `src/data/dungeonEvents.ts`

### 2.2 データアーキテクチャ
各種データはコード内のモジュールで定義され、ゲームロジックが直接参照する。

* `src/data/spells.ts`: 呪文データ
* `src/data/monsters.ts`: モンスター定義
* `src/data/map1.ts`: ダンジョンフロア定義
* `src/data/items.ts`: アイテム・装備定義
* `src/data/dungeonEvents.ts`: 探索イベントデータ

## 3. キャラクター & パーティ仕様

### 3.1 パーティ構成
* 最大5人のパーティ。
* 前衛は先頭3名、後衛は最後2名。
* 後衛キャラクターは近接武器攻撃を実行できない。
* 前衛にいる遠隔武器攻撃は不利判定になる。

### 3.2 キャラクター状態
各キャラクターは以下の情報を持つ。
* `id`, `name`, `class_id`, `level`, `xp`
* 能力値: `str`, `dex`, `con`, `int`, `wis`, `cha`
* HP: `current`, `max`
* `hit_dice_remaining`
* `spell_slots`（レベル別スロット）
* `ac`
* `position`: `front` / `back`
* `is_alive`, `status_effects`
* 装備: `equipped_weapon_id`, `equipped_armor_id`, `equipped_shield_id`

### 3.3 AC計算
* 基本AC = `10 + DEX修正値`
* 装備中の防具がある場合はその `ac_bonus` を使用し、盾の `ac_bonus` を加算する。

### 3.4 クラス定義と成長
現行実装は以下のクラスを中心に運用する。

| クラス | ヒットダイス | レベルアップ時HP増加 | 備考 |
| --- | --- | --- | --- |
| fighter | d10 | `6 + CON修正値` | 前衛向け高耐久 |
| rogue | d8 | `5 + CON修正値` | 機動系・後衛運用も可 |
| cleric | d8 | `5 + CON修正値` | 回復支援役 |
| wizard | d6 | `4 + CON修正値` | 範囲/攻撃呪文担当 |

* レベル1のHPはクラスごとの初期テンプレート値で固定。
* レベルアップ時はダイスではなく固定値 + CON修正値で最大HPを増加。
* `SPELL_SLOTS_TABLE` に基づき、レベルに応じて呪文スロットを更新する。

### 3.5 パーティ管理
* `GuildModal` でパーティ編成、メンバー追加・削除、名前変更が可能。
* 新規キャラクター作成時は 4d6 方式で能力値を生成。
* 新規キャラクターはパーティが5人未満なら自動的にパーティに追加される。

## 4. 探索 & ダンジョン仕様

### 4.1 ゲームシーン
* `town`: 街
* `dungeon`: 地下迷宮探索
* `battle`: 戦闘
* `camp`: 野営地

### 4.2 ダンジョンマップ
* ダンジョンは15x15のグリッド。
* 各タイルは 4 方向の壁状態とイベント情報を保持する。
* マップは `src/data/map1.ts` で `map1Data`, `map2Data`, `map3Data` として定義される。

### 4.3 移動操作
* 操作: 前進 / 後退 / 左回転 / 右回転。
* 壁や `locked_door` は移動不可。
* `door` は通過時に開けて進む。
* 移動先のタイルに `event` があれば `triggerEvent()` が実行される。

### 4.4 階段移動
* `stairs_up` / `stairs_down` は `useStairs()` でフロア移動を処理。
* 目的フロアが存在しない場合は街への帰還を処理する。

### 4.5 エンカウント
* 移動後に現在フロアの `encounter_table.rate` でランダムエンカウント判定。
* 出現モンスターは `encounter_table.monsters` で重み付き抽選。
* 1〜2体のモンスターが生成される。

### 4.6 探索イベント
* `dungeonEvents.ts` による `chest`, `door`, `trap` 等のイベントを実装。
* イベントはモーダル表示で担当キャラクターと選択肢を選ぶ。
* 判定は `1d20 + 能力修正値` で行い、DC と比較する。
* 成功で報酬、失敗でペナルティ（ダメージ）が適用される。
* 現行実装では受動知覚の自動判定や罠解除専用フローは未実装。

## 5. アイテム・装備・ショップ

### 5.1 アイテム体系
`src/data/items.ts` では以下の種類を扱う。
* `consumable`: 回復薬など
* `weapon`: 武器
* `armor`: 防具・盾

### 5.2 インベントリ管理
* `inventory` は `itemId` と `quantity` の配列で管理。
* `InventoryView` で対象キャラクターを選択し、使用・装備・外す操作が可能。

### 5.3 装備システム
* 武器は `equipped_weapon_id`、防具は `equipped_armor_id`、盾は `equipped_shield_id`。
* 装備変更時は `ac` を再計算する。
* 売却時は装備中アイテムの状態を考慮する。

### 5.4 消費アイテム
* `useItem(itemId, targetCharacterId)` によって回復を実行。
* 回復効果は `heal_dice` を用いて算出し、HP を最大まで回復する。
* 使用後はインベントリ数量を減少させる。

### 5.5 ショップ
* `ShopModal` で購入・売却を行う。
* 購入価格は `value_gp`、売却価格はその半額。
* 所持金不足だと購入できない。

### 5.6 寺院
* `TempleModal` で単体回復と蘇生を提供。
* 治療: 15 Gで対象キャラクターのHPを最大まで回復。
* 蘇生: 50 Gで死亡キャラクターを復活させ、HPを半分程度回復。

### 5.7 宿屋
* `TownView` の宿屋で 10 G を支払い、パーティ全員のHPを全回復する。

## 6. 休憩システム

### 6.1 小休憩
* `shortRest()` でヒットダイスを1消費し、`1d8 + CON修正値` で回復。
* HPが満タン、あるいはヒットダイス残数が0のキャラクターは回復対象外。

### 6.2 大休憩
* `longRest()` で全キャラクターのHPを最大に回復。
* ヒットダイスと呪文スロットを全回復する。

---

## 7. 戦闘システム

### 7.1 戦闘開始
* `startBattle()` でエンカウントを発生させ、プレイヤーと敵のイニシアチブを決定。
* 敵は `monsterList` に定義されたモンスターから生成される。

### 7.2 イニシアチブ
* 参加者は `1d20 + DEX修正値` でイニシアチブを取得。
* イニシアチブの高い順に行動。

### 7.3 プレイヤーアクション
プレイヤーは以下を選択できる。
* 攻撃
* 呪文
* 道具
* 回避
* 逃走

### 7.4 攻撃判定
* `1d20 + attackBonus` で判定。
* 遠隔武器は DEX、近接武器は STR、または罠性質により DEX/STR を選択。
* 自然20はクリティカル、自動命中、ダメージダイス2倍。
* 自然1はファンブル、自動ミス。
* `attackRoll.total >= target.ac` で命中。

### 7.5 ダメージ計算
* 武器は `damage_dice` に能力修正値を加える。
* 呪文攻撃・回復は `damage_dice` / `heal_dice` を適用。
* HP は 0 になれば撃破とみなす。

### 7.6 呪文
* 呪文データは `src/data/spells.ts` で管理。
* キャンクリップ (level 0) はスロット消費なし。
* レベル1以上の呪文は対応するスロットを1消費。
* 呪文の効果は直接ダメージまたは回復として処理される。

### 7.7 敵の行動
* `processEnemyTurn()` で敵攻撃を実行。
* 射程武器は後衛も対象にできる。
* 近接攻撃は前衛を優先し、対象がいない場合は後衛も選択される。

### 7.8 逃走
* `attemptRun()` で `DEX修正値 + 5` で逃走判定。
* 失敗時は一部プレイヤーの行動をスキップする可能性がある。

### 7.9 戦闘報酬
* 敵1体あたり `50 XP`, `15 GP` を固定報酬として付与。
* 報酬獲得時に `ポーション` が追加される場合がある。
* `claimBattleReward()` で生存キャラクターに XP を分配し、`checkLevelUp()` を実行する。

## 8. UI / UX

### 8.1 画面構成
* `GameContainer` が全体を統括。
* `DungeonView`, `BattleView`, `TownView`, `CampView` を切り替え表示。
* `StatusPanel` でパーティステータスを表示。
* `MessageLog` で行動ログを表示。
* `CharacterDetailModal` で詳細を確認できる。

### 8.1.1 行動ログの色分け
* `player_action` - 青: 正常なプレイヤー行動や通常攻撃のログ。
* `enemy_action` - 赤: 敵の通常行動・ダメージログ。
* `heal` - 緑: 回復・治療効果。
* `critical` - 黄/オレンジ: クリティカルヒットや重要な成功。
* `system` - 紫: システムメッセージ、判定失敗、行動不可、ミスなど。
* `info` - 白: 通常の状態変化、出現、勝利メッセージなどの中立ログ。

### 8.2 ダンジョン画面
* 5x5 のミニマップ表示。
* 現在位置と向きを表示。
* `前進`, `後退`, `左回転`, `右回転`, `調べる`, `キャンプ` を操作。
* イベントタイルは `?` などで示唆され、発見時にイベントモーダルを開く。

### 8.3 戦闘画面
* イニシアチブバーで行動順を表示。
* 敵と味方のステータスを表示。
* 呪文 / 道具選択時は対象を選択して発動する。
* `逃走` ボタンを実装。

### 8.4 街画面
* 宿屋、ショップ、寺院、ギルドの各機能をボタンで提供。
* 宿屋は全HP回復、ショップは売買、寺院は治療/蘇生、ギルドは編成管理。

### 8.5 キャンプ画面
* パーティ状態を表示。
* `小休憩` / `大休憩` が実行可能。

---

## 9. 補足
* 現行実装では外部JSONではなく TypeScript データモジュールでコンテンツを管理する。
* 受動知覚や罠解除の自動判定は実装されておらず、探索イベントは選択肢ベースで処理される。
* ゲーム進行は `src/store/useGameStore.tsx` の Zustand ストアで一元管理される。
